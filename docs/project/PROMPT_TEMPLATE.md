# NexLed Reusable Task Prompt

Copy this template for implementation tasks in NexLed or consumer projects.

```md
## Reference
- Visual reference:
- Files being touched:
- Components in scope:

## Mode
- REPLICATE / RESTRUCTURE / HYBRID / CONTENT / ORGANIZE / ANALYZE

## Required Reads
1. `codex_nexled_reusable_prompt.md`
2. `CLAUDE.md`
3. `docs/project/ROADMAP.md`
4. `docs/guides/RESPONSIVE_RULES.md`
5. Published NexLed sources:
   - `src/config-cdn.js`
   - `src/nexled.css`
   - `COMPONENTS.md`

## Hard Constraints
- Copy existing NexLed component markup before inventing anything.
- No `<style>` blocks.
- No inline `style=""`.
- No local CSS files.
- No arbitrary Tailwind values.
- No invented classes, tokens, variants, or breakpoints.
- Use `nexled.js` only when interaction is required.

## Work Order
1. Brief intent + mode
2. Files touched
3. Section-by-section implementation
4. Interaction/state behavior
5. Validation checklist result
6. Outstanding constraints or assumptions

## Validation Checklist
- Sources were read first.
- Required head block is correct.
- Styling uses published NexLed classes only.
- Value decisions use published tokens only.
- States are covered where relevant.
- Responsive behavior is preserved.
- No out-of-scope changes were made.
```
